# M16 — Security Audit

Status: M16 audit of the implementation as it exists on `feature/security-hardening` (branched from
`feature/privacy-gdpr`, M15). Audited 2026-09-26.

This audit records what the **code** does, verified by reading it and, where noted, by running it
(an in-process probe of the real Fastify stack, `pnpm audit`, a git-history scan). Where the code
and older documentation disagreed, the code wins and the difference is noted. It is a
risk-reduction exercise, not a certification: nothing here claims the application is "secure" or
"compliant" with any standard.

Related: [risk register](M16-RISK-REGISTER.md) · [threat model](M16-THREAT-MODEL.md) ·
[authorization matrix](M16-AUTHORIZATION-MATRIX.md) · [security tests](M16-SECURITY-TESTS.md) ·
[sources](M16-SECURITY-SOURCES.md) · [baseline](security-baseline.md) · [ADR-027](../adr/adr-027-security-hardening.md)

## 1. Scope and method

Inspected: `apps/api` (server, hooks, every route, logging, composition), `apps/web` (router,
guards, storage, services, Vite config, build output), `packages/config` (environment),
`packages/application` (identity, privacy, teaching, audio/video use cases), `packages/data`
(repositories, SQL read models, migrations, provider adapters), `packages/contracts`, `content/`,
`tests/e2e`, `Jenkinsfile`, `sonar-project.properties`, `.husky/`, `.gitignore`, `.env.example`,
`infrastructure/`, all ADRs and `.claude/` context files.

Runtime checks (2026-09-26):

- An in-process probe of `buildServer` with the test composition (headers and bodies of `/health`,
  an unknown route, malformed JSON, an oversized body, a wrong content type, an `OPTIONS` preflight
  from a foreign origin, a rate-limited login).
- `pnpm audit` (full and `--prod`).
- A pattern scan of every commit on every branch (`git grep` over `git rev-list --all`) for API
  keys, tokens and private keys, plus a scan of every file name ever committed for `.env`, keys and
  certificates.

## 2. Existing controls (verified in code)

| Area                 | Control                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Password storage     | Argon2id via `argon2@0.45.1`, library defaults **m=65536 KiB, t=3, p=4** (above OWASP's minimum m=19 MiB, t=2, p=1), random salt per hash, `argon2.verify` comparison. Policy 8–128 characters, no composition rules. Hash never leaves the domain (`toSafeUser`, allowlisting response schema).                                                                        |
| Login                | Generic `401 Invalid email or password.`; a dummy Argon2id hash with the same parameters is verified when the account does not exist (timing). New random session token per login (no fixation).                                                                                                                                                                        |
| Sessions             | Server-side `sessions` table; 256-bit CSPRNG token (`randomBytes(32)`), stored as SHA-256; cookie `tfm_bic_session` `HttpOnly`, `SameSite=Strict`, `Secure` in staging/production, `Path=/`, signed (HMAC) by `@fastify/cookie`; 7-day absolute expiry; logout deletes the row; password reset and account deletion delete every session of the user.                   |
| Reset / verification | 256-bit CSPRNG tokens stored as SHA-256; reset 1 h, verification 24 h; a new request invalidates earlier unused tokens; generic responses for register, resend and reset-request; links built from `APP_BASE_URL`, never the `Host` header; request logs drop query strings.                                                                                            |
| Authorization        | `authenticate` preHandler (session → `request.currentUser`); `requireRole` for the teacher dashboard; every "my data" route derives the user from the session — no `:userId` anywhere; teacher reads start from a roster CTE scoped to the session teacher; foreign/missing resources are the same `404`. Details: [authorization matrix](M16-AUTHORIZATION-MATRIX.md). |
| Mass assignment      | `.strict()` Zod request schemas everywhere; use-case inputs carry no role/user/score fields; fields mapped one by one.                                                                                                                                                                                                                                                  |
| Business logic       | Server judges every answer; client cannot send a verdict/score/points; points only from `AwardRewardsUseCase` with unique `(user_id, reason, source_id)` and advisory lock; ledger append-only (trigger); forward-only progress with atomic upserts.                                                                                                                    |
| Answer keys          | Presenters build student views field by field; allowlisting response schemas; raw-body tests per exercise type and a Playwright spec that records every exercise response.                                                                                                                                                                                              |
| Injection            | Drizzle parameterised queries; the only `sql.raw` uses are fixed allowlisted `ORDER BY` fragments keyed by a validated enum (teacher roster); teacher search uses `strpos` on a bound parameter (no `LIKE` pattern from input). Hyperframes CLI runs through `execFile` (no shell).                                                                                     |
| XSS                  | React text rendering only; `no-raw-html.test.ts` forbids `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `new Function` and computed dynamic imports in `apps/web` and `packages/ui`; content schemas reject markup; email templates escape every variable.                                                                                                             |
| CSRF                 | `SameSite=Strict` session cookie + `Origin` check (`verify-origin.ts`) on every state-changing route except one-click unsubscribe (token-authorized); the API only parses `application/json` (a cross-site form post is a `415`); no CORS headers are emitted, so cross-origin preflights fail (`OPTIONS` → `404`).                                                     |
| Rate limiting        | `@fastify/rate-limit` per route (auth, catalog, lessons, exercises, gamification, vocabulary, phonetics, video, audio, teacher, email preferences, data management) — keyed by client IP only.                                                                                                                                                                          |
| Logging              | Redacts `cookie`/`authorization`/`set-cookie`; request logs drop the query string; allowlisting error serializer and `logMethod` hook strip SQL parameters and driver `detail` (M15); events carry ids only.                                                                                                                                                            |
| Provider isolation   | Gemini key only server-side (`GEMINI_API_KEY`), refused under `NODE_ENV=test`; `fake` default for audio, video and email; the client never sends text to synthesise (the server takes it from content); fixed provider URL (no user-controlled fetch); 20 s timeout, bounded retries, raw provider text never propagated.                                               |
| Test-only routes     | `/auth/_test/emails`, `/email-preferences/_test/newsletter-issues`, `/teacher-dashboard/_test/links` exist only when `NODE_ENV=test` **and** the E2E composition enables them.                                                                                                                                                                                          |
| Privacy (M15)        | Export and deletion on the session user only; deletion needs Origin + current password + `confirm: true`, one transaction, all sessions die; export is `private, no-store`, `attachment`, allowlisted columns, no secrets.                                                                                                                                              |
| Client storage       | `localStorage` holds only the theme; the session cookie is `HttpOnly`; no token in JS; user-scoped TanStack Query caches are cleared on logout/login; no `VITE_*` variables are read; no source maps in the production build.                                                                                                                                           |
| Secrets in Git       | No API key, token or private key found in any commit on any branch; `.env.example` only ever contained non-secret defaults. The only committed credentials are the documented dev-only Postgres password in `infrastructure/docker/docker-compose.yml` and a throwaway E2E cookie secret in `tests/e2e/playwright.config.ts`.                                           |
| Supply chain         | `pnpm install --frozen-lockfile` in CI; exact `packageManager` pin (`pnpm@12.4.2`); `.nvmrc` = 24; Playwright image pinned to the lockfile version.                                                                                                                                                                                                                     |

Not present (so not audited as attack surface, and **not** created by M16): file/media upload,
user-supplied URLs fetched by the server (no SSRF surface), webhooks, OpenAPI/Swagger, admin UI,
email change, password change (only reset), MFA, CORS, a production Dockerfile, a reverse-proxy
config (`infrastructure/nginx` is a README only), a deployed environment, backups.

## 3. Findings

Severity reflects the current code **and** its intended deployment (a single API instance behind
a host that is still PENDING, ADR-015). Statuses were recorded before implementation and are updated in [§6](#6-outcome) once each fix is verified.

| ID   | Severity | Component                          | Finding                                                                                                                                                                                                                                                                                                                                                                      | Remediation                                                                                                                                                                                                                                                     | Status          |
| ---- | -------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| S-01 | HIGH     | API server / rate limiting         | Every rate limit is keyed by `request.ip`, and Fastify's `trustProxy` is unset. Behind any reverse proxy or PaaS router (the likely hosting), all clients share the proxy's address: one person exhausts login (10/15 min), registration and reset for **everyone**. Setting `trustProxy: true` instead would let any client spoof `X-Forwarded-For` and bypass every limit. | `TRUST_PROXY` setting: an explicit IP/CIDR allowlist (Fastify 5.12 no longer accepts hop counts), validated at start-up, default "trust nothing". Deployment docs say when to set it.                                                                           | Planned (M16)   |
| S-02 | MEDIUM   | Auth / login                       | Login is throttled only per IP. A distributed guess against one account (many addresses) is unbounded.                                                                                                                                                                                                                                                                       | Second, per-account limit keyed by the normalised email (counted for existing and non-existing addresses alike, so it reveals nothing). Reset stays available (OWASP lockout-DoS note).                                                                         | Planned (M16)   |
| S-03 | MEDIUM   | Privacy / account deletion         | Deletion checks the current password but is limited per IP only: a stolen session plus rotating addresses can guess the password — and success deletes the account.                                                                                                                                                                                                          | Per-user limit (session user id) in addition to the per-IP one; same for export.                                                                                                                                                                                | Planned (M16)   |
| S-04 | MEDIUM   | Audio / video generation           | Cost-bearing generation is limited per IP: a class behind one NAT shares one budget, and an attacker with many addresses is unbounded (financial risk once a paid provider is enabled).                                                                                                                                                                                      | Per-user limits added on top of the per-IP ones.                                                                                                                                                                                                                | Planned (M16)   |
| S-05 | MEDIUM   | Auth / reset + verification tokens | Token use is check-then-act: `findByTokenHash` → check `usedAt` → change → `markUsed` (unconditional `UPDATE`). Two concurrent requests with one token both succeed, and a failure between the password update and `markUsed`/session revocation leaves the token reusable and old sessions alive.                                                                           | Atomic single-use consumption (`UPDATE … WHERE used_at IS NULL AND expires_at > now RETURNING`) **before** any change; typed errors preserved.                                                                                                                  | Planned (M16)   |
| S-06 | MEDIUM   | HTTP hardening (API + SPA)         | The API sends no security headers (no `nosniff` outside two routes, no frame protection, no referrer policy); responses without an explicit `Cache-Control` (e.g. `/auth/me`, `/auth/login`, `/profile`) carry none. No CSP exists anywhere for the SPA (the nginx config was never created). Reset links put the token in the page URL, which a `Referer` could leak.       | API: baseline headers on every response, `Cache-Control: no-store` unless a route chooses otherwise, HSTS in staging/production. SPA: one CSP/header policy in code, served by `vite preview` and required of the host; E2E runs the production build under it. | Planned (M16)   |
| S-07 | LOW      | Error handling                     | The central error handler answers `{"error":"Internal Server Error"}` to every Fastify-raised client error — malformed JSON (`400`), oversized body (`413`), wrong content type (`415`) and **rate limiting (`429`)** — and logs them all at `error` level, so any client can flood error logs.                                                                              | Safe message per status; `4xx` logged at `info` without stack; `5xx` unchanged (generic, logged).                                                                                                                                                               | Planned (M16)   |
| S-08 | LOW      | Error handling / observability     | Fastify's default `404` reflects the requested path; request ids are sequential per process (`req-1`…) and never returned to the client, so a user-reported failure cannot be correlated with a log line.                                                                                                                                                                    | Generic `404` body; random UUID request ids returned in `X-Request-Id` (never accepted from the client).                                                                                                                                                        | Planned (M16)   |
| S-09 | MEDIUM   | Configuration                      | In staging/production `AUTH_SESSION_SECRET` accepts any non-empty string (e.g. `secret`), and `APP_BASE_URL` silently defaults to `http://localhost:5173` — email links would point at localhost over HTTP and the Origin check would expect it.                                                                                                                             | Staging/production: secret ≥ 32 characters, `APP_BASE_URL` required and `https:`.                                                                                                                                                                               | Planned (M16)   |
| S-10 | LOW      | API server / resource limits       | Fastify defaults: `requestTimeout` 0 (Fastify's own docs say to set it when not behind a proxy — slow-request DoS) and a 1 MiB body limit for every route without its own (all auth routes).                                                                                                                                                                                 | Server-wide `requestTimeout` and a 16 KiB default body limit (routes keep their smaller limits).                                                                                                                                                                | Planned (M16)   |
| S-11 | MEDIUM   | Git hygiene                        | `.gitignore` ignores `.env`, `.env.local` and `.env.*.local` but **not** `.env.production`, `.env.staging`, `.env.development` or `.env.test` — an obvious place to put real secrets.                                                                                                                                                                                        | Ignore `.env.*` except `.env.example`.                                                                                                                                                                                                                          | Planned (M16)   |
| S-12 | LOW      | Local infrastructure               | The dev Postgres container publishes `5432` on all interfaces with a committed password — reachable from the local network.                                                                                                                                                                                                                                                  | Bind to `127.0.0.1`.                                                                                                                                                                                                                                            | Planned (M16)   |
| S-13 | LOW      | CSRF                               | `verify-origin` accepts requests without `Origin`. Modern browsers send it on every `POST`, so this is defence in depth only, but OWASP recommends blocking or a Fetch Metadata fallback.                                                                                                                                                                                    | When `Origin` is absent, refuse a request whose `Sec-Fetch-Site` is `cross-site` or `same-site`.                                                                                                                                                                | Planned (M16)   |
| S-14 | LOW      | Rate limiting                      | `GET`/`PATCH /profile` have no rate limit (a known M4 rough edge).                                                                                                                                                                                                                                                                                                           | Reads 120/min, writes 30/min per client.                                                                                                                                                                                                                        | Planned (M16)   |
| S-15 | LOW      | Configuration                      | `E2E_RELAXED_RATE_LIMITS=true` (every limit × 100) is accepted in any `NODE_ENV`, including production.                                                                                                                                                                                                                                                                      | Refuse it unless `NODE_ENV=test`.                                                                                                                                                                                                                               | Planned (M16)   |
| S-16 | MEDIUM   | CI/CD supply chain                 | No dependency-audit step and no secret scanning in the `Jenkinsfile`.                                                                                                                                                                                                                                                                                                        | `pnpm audit --prod --audit-level=high` stage. Secret scanning (gitleaks) documented as PENDING: Docker was not available to verify it here.                                                                                                                     | Planned (M16)   |
| S-17 | MEDIUM   | Auth / enumeration by timing       | Register, resend-verification and reset-request return the same body for existing and unknown accounts, but do extra database writes (and an email call) only for existing ones. With the fake provider the difference is milliseconds; a real provider call would make it measurable.                                                                                       | Accepted for now; move email delivery off the request path (outbox/background send) when ADR-014 selects a provider.                                                                                                                                            | Open (accepted) |
| S-18 | LOW      | Sessions                           | 7-day absolute lifetime, no idle timeout, no `__Host-` cookie prefix, expired session rows never purged.                                                                                                                                                                                                                                                                     | Accepted trade-off for a learning app (documented, ADR-027); revisit before storing more sensitive data.                                                                                                                                                        | Open (accepted) |
| S-19 | LOW      | CI/CD                              | The Jenkins controller has the host Docker socket (root-equivalent on the host).                                                                                                                                                                                                                                                                                             | Documented; not redesigned in M16 (Jenkins is a local, single-user controller).                                                                                                                                                                                 | Open (accepted) |
| S-20 | INFO     | Dependencies                       | `pnpm audit`: 1 moderate — `esbuild ≤ 0.24.2` (GHSA-67mh-4wv8-2f99, dev server CORS) via `drizzle-kit` → `@esbuild-kit/*`. Dev-only; drizzle-kit never starts an esbuild dev server. `pnpm audit --prod`: none.                                                                                                                                                              | Accepted; re-check on every drizzle-kit upgrade.                                                                                                                                                                                                                | Open (accepted) |

No finding was rated CRITICAL: no authentication bypass, IDOR, injection, answer-key leak,
points manipulation or committed secret was found.

## 4. Areas checked with no new finding

- **IDOR/BOLA** — no route takes a user id; teacher access goes through the roster; video jobs and
  teacher students answer the same `404` for "missing" and "not yours". See the matrix.
- **Answer keys, points, achievements, completion** — server-authoritative, already covered by
  M7/M8 tests; M16 adds a route-inventory guard, not a new mechanism.
- **SQL injection** — see §2; no string-built SQL from input.
- **XSS** — see §2; no HTML rendering path exists.
- **SSRF** — the server fetches only the fixed Gemini endpoint (not reachable in tests/CI) and
  never a user-supplied URL. No protection was added because there is no surface.
- **File upload / media** — none exists. Generated audio is returned inline (`audio/wav`,
  `private, no-store`, `nosniff`) and never stored; video `mediaReference` is never exposed as a
  URL.
- **Open redirects** — the only post-login redirect uses React Router history state
  (`location.state.from.pathname`), which a cross-site attacker cannot set; no `next=`/`returnUrl`
  parameter exists.
- **Webhooks** — none. **OpenAPI** — none.
- **Health endpoints** — `/health` returns status, timestamp and default language; `/ready`
  returns `{ ready: true }`. No secret, version or dependency detail.
- **Email links** — always built from `APP_BASE_URL` (S-09 now forces HTTPS in production).
- **Frontend environment** — no `VITE_*` variables; nothing secret can reach the bundle.
- **Test data** — synthetic `example.com`/`example.test` addresses; no real personal data.
- **Database** — application uses one `DATABASE_URL`; least-privilege roles, TLS and backups depend
  on the hosting decision (ADR-005/015) and are recorded as risks, not implemented.

## 5. Documentation vs code

- `security-baseline.md` said "secure headers … set at the API/reverse-proxy layer
  (`infrastructure/nginx/`)" — nothing set any header; `infrastructure/nginx` holds only a README.
- `security-baseline.md` described the Origin check as applying to "`/auth/*` routes" — it applies
  to every state-changing route (better than documented).
- `require-role.ts` says "no M3 route uses it for real yet" — the teacher dashboard (M13) uses it.
