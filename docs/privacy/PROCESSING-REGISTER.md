# Technical processing register

Status: LIVE — engineering register. Not legal advice and **not** a legal record of processing activities —
see the [disclaimer](README.md). Legal bases are not assigned by engineering: every one is
**PENDING — REQUIRES PRODUCT/LEGAL DECISION** unless stated otherwise below.

The only processing whose basis is established by the product design is the newsletter, which runs only on
explicit, recorded consent (M14, ADR-025) — whether that design is legally sufficient is itself pending review.

## Retention register

No retention period is invented. Where the current behaviour is "until account deletion", that is a description,
not a legal decision.

| Data                                | Current retention behaviour                                                                                                                        | Proposed product behaviour                                    | Legal/product decision needed                                 | Status  |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------- | ------- |
| Account, profile, learning records  | Until the user deletes the account                                                                                                                 | Same                                                          | Whether inactive accounts should be deleted after some period | PENDING |
| Expired/used sessions and tokens    | Logout and password reset delete sessions; expired sessions and used/expired tokens stay until account deletion (never honoured once expired/used) | A cleanup job for expired/used rows is technically reasonable | None legal; an engineering decision for a later milestone     | PENDING |
| Newsletter record after unsubscribe | Kept (status `unsubscribed`, timestamps)                                                                                                           | Keep as evidence of withdrawal until account deletion         | How long evidence of consent/withdrawal must/may be kept      | PENDING |
| Exercise attempts (append-only)     | Until account deletion                                                                                                                             | Same                                                          | Whether old attempts should be aggregated/pruned              | PENDING |
| Server logs (IP, user ids)          | Whatever the hosting platform keeps                                                                                                                | Set at hosting selection                                      | Log retention period; ADR-015 hosting                         | PENDING |
| Backups                             | Not provisioned                                                                                                                                    | Set at DB provisioning                                        | Backup retention and deletion propagation                     | PENDING |
| `FakeEmailProvider` capture         | Last 500 messages in memory, lost on restart                                                                                                       | Removed when a real provider replaces the fake                | ADR-014 provider selection                                    | PENDING |

No scheduled destructive job was added in M15: no retention rule is defined.

## Privacy notice: information vs acknowledgement vs consent

| Concept                       | What exists                                                                                                 | Status                                                                                                                        |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Information (the notice)      | `/privacy`, version `privacy-policy-v1`, linked from footer and registration                                | Implemented — draft pending legal review                                                                                      |
| Acknowledgement of the notice | **Not recorded.** Registration links to the notice; there is no checkbox and no stored record               | PENDING product/legal decision: whether acknowledgement must be recorded, and at which events (registration, material change) |
| Marketing consent             | `newsletter_subscriptions.consent_version` (the consent **text** version, separate from the notice version) | Implemented (M14)                                                                                                             |

If acknowledgement recording is decided, the record would reference `privacy-policy-vN` ids, which are never
reused (see `apps/web/src/legal/privacy-notice.ts`).
